# Architecture

Swift package (`Package.swift`) with three targets: `BeamCore` (`Sources/BeamCore`, a library holding all the code, about 1,500 lines), `Beam` (`Sources/Beam`, an executable that is only `main.swift`) and `BeamTests` (`Tests/BeamTests`). The split exists so tests can `@testable import BeamCore`; see [testing.md](testing.md). Its third-party dependencies are [KeyboardShortcuts](https://github.com/sindresorhus/KeyboardShortcuts) (MIT) and [Sparkle](https://sparkle-project.org) (updates), both credited in `THIRD_PARTY_NOTICES.txt`. It runs as a menu bar accessory app with no Dock icon.

## Flow

1. The hotkey (KeyboardShortcuts) calls `SearchPanel.toggle()`.
2. `show()` calls `SearchIndex.refreshLive()`, which reloads windows, Chrome tabs, tab groups, Claude Code sessions and Slack in the background. Apps are loaded at launch and again when `AppWatcher` sees the app folders change, never on the hotkey. When a refresh lands while the panel is open, the selected row is kept by `SearchItem.identity` unless the query changed.
3. Each keystroke calls `SearchIndex.search()`, which scores every item with `Matcher` and returns the top 9.
4. Return runs the item's `activate` closure, which focuses the app, window or tab, or opens the Claude session or Slack conversation.

## Files

- **main.swift** (the only file in `Sources/Beam`): starts NSApplication with `AppDelegate`, which is `public` for that reason. Everything below is in `Sources/BeamCore`.
- **AppWatcher.swift**: an FSEvents stream on `AppProvider.roots` (2 s latency, which debounces installers) that calls `SearchIndex.refreshApps()`; changes inside `.app` bundles are ignored.
- **AppDelegate.swift**: creates the menu bar item (with About, which shows the version and the `BeamCommit` git commit the Makefile stamps into Info.plist), `SearchIndex`, `SearchPanel` and Settings. Owns the `SPUStandardUpdaterController` (Sparkle) behind the "Check for Updates…" menu item; none in the `.sandbox` bundle. Prompts for Accessibility permission and opens Settings on first launch (`didShowSettingsOnce` in UserDefaults).
- **SearchIndex.swift**: `SearchItem` (kind, title, subtitle, match keys, optional stable `id`, icon, `activate` closure) and `SearchIndex`, which holds the item lists and runs the search (the pure `SearchIndex.rank`, which tests call directly), ranking kinds by the user's order (`KindOrder`, default window, tab, group, closed group, app, Claude session, Slack; kinds can be switched off, and then their provider doesn't run; see 0016), and apps above tabs that matched only via `secondaryKeys` (the URL). Each provider runs at most once at a time (a refresh asked for mid-run reruns once afterwards). All AppleScript goes through `AppleScript.run`, one serial queue, and every script checks `is running` so it never launches Chrome. It also contains the built-in providers, each an enum with a `load()` function (a provider that reads another app's own data lives in its own file, see 0014):
  - `AppProvider`: scans `/Applications`, `/System/Applications`, `~/Applications` and similar folders, plus one level of subfolders (vendor folders like `DaVinci Resolve/`). Titles are the Finder display name in the user's language (needs `CFBundleAllowMixedLocalizations` in Info.plist); the file name stays a key.
  - `WindowProvider`: lists windows through the Accessibility API (`AXUIElement`), including windows on other Spaces via `SpaceWindows`. It returns nothing, silently, if Beam lacks Accessibility permission. Chrome is skipped because tabs cover it.
  - `ChromeProvider`: lists tabs through AppleScript (`NSAppleScript`), matching on title and the URL's host and path. Focuses a tab by Chrome's stable tab `id` (any window), falling back to URL + title, and does nothing if the tab is gone (0011); then makes that window Chrome's main window through the Accessibility API before activating Chrome. If Automation is denied (-1743) it returns a hint row that opens that Settings pane.
  - `ChromeGroupProvider`: finds tab groups by walking Chrome's own UI through the Accessibility API. Headers and membership are structural (an empty AXTabGroup with DOM class `TabGroupHeader…`, then the tabs after it); only the name is parsed from the localized header title (`parseHeader`, `layout`, `dropGroupWord`).
- **SettingsPanes.swift**: `SettingsPaneProvider` lists System Settings panes (`ItemKind.settingsPane`) by reading the Info.plists of `/System/Library/ExtensionKit/Extensions/*.appex` that are Settings extensions, localized names included, and opens one with `x-apple.systempreferences:<bundle id>` (0019). No hardcoded list, no permissions.
- **ClaudeSessions.swift**: `ClaudeSessionProvider` lists Claude Code sessions from Claude desktop's store (`~/Library/Application Support/Claude/claude-code-sessions/*/*/local_*.json`, archived ones skipped, most recently focused first) and opens one with `claude://code/continue?session=<id>` (built with `URLComponents`). Parsed files are cached by modification date, so a panel open only decodes sessions that changed. A worktree session shows its repo (`originCwd`) and `worktreeName`, falling back to the `.claude/worktrees/` path when Claude leaves those null. Needs Claude installed, no permissions.
- **ProviderHealth.swift**: notices when Claude Code sessions or Slack stop parsing (decision 0015). Each load passes an `Observation` (ok, noData, or broken with a closed `Kind`, plus files seen and parsed); state is kept per provider in UserDefaults, and a failure seen on 3 loads over 24 h on one version of the other app returns a notice row, matched by the app's name. `showReport` shows the exact report text (versions, provider, kind, counts; never user content) and opens a prefilled GitHub issue, an email to support@, or copies it. Settings lists confirmed failures. A `noAccess` outcome (macOS refused the read) is not a failure: it clears any broken state, returns a "needs access" row at once (hideable from results), and Settings shows it with a button to Full Disk Access (0017). Notice rows rank after real matches (0018).
- **Slack.swift**: `SlackProvider` reads Slack desktop's client state from its IndexedDB blob file (`~/Library/Application Support/Slack/IndexedDB/https_app.slack.com_0.indexeddb.blob/`, newest file wins, decoded result cached until the file changes) and lists channels you're in, people (bots, deactivated and you skipped) and group DMs, each opened with a `slack://channel` or `slack://user` link; a person you have a DM with opens the DM. Conversations you're in (channels, group DMs, people you have a DM with) get `SearchItem.boost`: a base that beats any name-length tiebreak, so they rank above strangers, plus a recency share (Slack's own `channelsPriority`, or how recent `channelLatests` says the last message is, fading over 90 days; a person uses their DM's). It is capped at `Matcher.maxBoost`, so it reorders within a match tier but never lifts an item into a better one. `SlackCache` decodes the value: Chromium's Snappy wrapper, Blink's envelope, then V8's serialization format into a `JSValue`. Messages are decoded with the rest but never used or shown. Needs Slack installed. `SlackPaths` picks the direct download's folder, else the Mac App Store container, which needs macOS's "access data from other apps" consent (asked at launch, when the first refresh reads it). People show their Slack photo: `SlackAvatars` reads it from Slack's own Chromium disk cache (`Cache/Cache_Data`, "simple cache" format), where the file name is the first 8 bytes of SHA-1(`1/0/<url>`), little-endian, in hex, plus `_0`, so each photo is one file read; it falls back to the Slack icon, and a miss isn't retried until Slack's state changes. See decision 0012.
- `SearchScope` (in SearchIndex.swift): items with a `scope` (Slack) are left out of plain queries; a leading `@` or `#` searches only that scope (people and group DMs, or channels); alone, it lists that scope's items with a boost, highest first.
- **Matcher.swift**: `normalize` folds case, diacritics, width and Hebrew/Arabic points (ASCII takes a fast path); scoring tiers exact > prefix > word-prefix > substring > fuzzy (letters in order), with shorter targets winning ties. A query of 2+ words also matches at the substring tier when each word starts a different target word, in any order ("mobile-core" finds "core-mobile-team-devs", like Slack).
- **SearchPanel.swift**: the floating panel (styled after macOS 26 Spotlight) on the screen with the mouse: text field, results table, keys (arrows, Return, Esc), and hides when it loses focus.
- **BeamIconView.swift**: the animated search icon (pixel art "beams in", then crossfades to the detailed icon).
- **CodeSigning.swift**: reads the running app's signing team ID; `AppDelegate` starts Sparkle only when it matches Beam's (0010).
- **Favicons.swift**: reads tab favicons from Chrome's own `Favicons` SQLite databases, one per profile, read from a cheap copy (APFS clone of the DB and its WAL, re-made only when they change) because Chrome keeps the live file locked. The in-memory cache is pruned to the current tabs' URLs.
- **SpaceWindows.swift**: private APIs for windows on other Spaces: enumerates an app's windows by AX remote token, and focuses a window through SkyLight so macOS switches to its Space (decision 0007).
- **Shortcuts.swift**: the hotkey name and its default (⌥⌘Space), plus detection of macOS shortcuts that already hold the chosen keys (such as Spotlight's ⌘Space).
- **SettingsWindow.swift**: SwiftUI Settings for the hotkey recorder, the "Use ⌘Space" walkthrough, and the launch-at-login toggle, plus an Acknowledgements… link that opens the bundled `THIRD_PARTY_NOTICES.txt` (shown only when the file is in the bundle).
- **AboutWindow.swift**: Beam's own About window (icon, version and build commit, supporter details, website and GitHub links), sized to its content; replaces the standard About panel, whose credits box scrolls and has a white background.
- **Licensing.swift / SupportWindow.swift**: the license key window ("Enter License Key…" in the menu bar and Settings, or a `beam://license?key=…` link from the website's thank-you page, handled in `AppDelegate.application(_:open:)`). Choosing an amount and paying happen on the website, not in the app (see 0008). `LicenseCheck.run` POSTs the key to `api.lemonsqueezy.com/v1/licenses/validate` once (10 s timeout, key never logged); `Licensing.parse` turns the reply into a result; success calls `Support.markSupporter(info)`, which also stores a `LicenseInfo` (plan, email, the key's last 4 characters, test mode; never the full key) that About shows, with a quiet "Receipts and billing" link to Lemon Squeezy's My Orders page. `validate` rather than `activate`: it changes nothing server-side and activations are unlimited. Together with the Sparkle update check (fetches `beamlauncher.app/appcast.xml`, downloads from `downloads.beamlauncher.app`, no system profile), this is Beam's only network traffic.
- **Support.swift**: the local beam counter and the gentle support reminder. It counts beams in UserDefaults and, for non-supporters, shows a short strip in the search panel after milestones (100, 1,000, 5,000 …). "Support Beam" (menu, panel pill and bar, ⌘D, Settings) opens `supportURL`, the website's support section. Supporter status is stored here.
- **LaunchAtLogin.swift**: uses `SMAppService`. It is turned on automatically the first time Beam runs from /Applications, not for dev builds.

## Build and packaging

- `Makefile`: `test` (`swift test`), `build`, `app` (bundles and ad-hoc signs `build/Beam.app`), `run`, `install` and `uninstall` (both in `scripts/`), `dmg`, `release`, `sandbox` and `run-sandbox`.
- `scripts/release.sh` (`make release`): builds via `make app`, re-signs with the Developer ID cert (hardened runtime, secure timestamp, `Resources/Beam.entitlements`), signing nested `.bundle`s first without `--deep`, builds and signs `build/Beam.dmg`, notarizes it with `notarytool` (profile `beam-notary`), staples and validates app and dmg. `SKIP_NOTARIZE=1` signs only. The dev `make app` path stays ad-hoc.
- `Resources/`: `Info.plist`, the icons, and `Beam-Sandbox.entitlements`, used only by the sandbox variant.
- `.github/workflows/test.yml`: `swift build` and `swift test` on a macOS runner for PRs and pushes to main.
- `mockups/`: HTML prototypes of the beam-in animation and the icons.
