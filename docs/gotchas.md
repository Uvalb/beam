# Gotchas

- Test-mode Lemon Squeezy keys validate fine against the live API but carry `test_mode: true`. `Licensing.acceptTestKeys` must be flipped to false at launch. 
- Swift Testing suites run in parallel with each other, so only one suite may touch `Support.d`.

- **Ad-hoc signing and permissions:** a plain ad-hoc signature's designated requirement is its cdhash, so every rebuild silently drops the Accessibility grant. The Makefile pins the requirement to the bundle ID (`-r='designated => identifier "…"'`) to avoid this; keep that flag on any new `codesign` call. A grant made before that change still has to be reset once with `tccutil reset Accessibility <bundle id>`.
- **No Accessibility permission:** `WindowProvider` returns a single "Grant Accessibility access" result (matched by "window" or "accessibility") that opens the right System Settings pane, instead of an empty list.
- **The App Sandbox blocks window listing:** even when the sandboxed app is trusted for Accessibility and signed with a Developer ID, every app refuses to list its windows (tested 2026-10-21). This is why Beam isn't on the App Store.
- **Sandbox and the home folder:** `NSHomeDirectory()` points into the app's container, so `~/Applications` and Chrome's favicon databases look empty. Use the real home folder (`getpwuid`).
- **The sandbox blocks the Accessibility prompt:** `AXIsProcessTrustedWithOptions(prompt: true)` shows nothing when sandboxed, so users must add the app by hand.
- **Several Beam copies:** builds from other worktrees can be running and holding the hotkey. Check with `pgrep -fl MacOS/Beam`.
- **zsh `log`:** use `/usr/bin/log`.
- **Raising a Chrome window:** AppleScript `set index of w to 1` only reorders the window; it doesn't make it Chrome's main window. If Chrome is activated after (or alongside) it, Chrome brings its old main window back on top, so the target flashes and vanishes. Set the window's `AXMain` (and `AXRaise` it) first, then activate.
- **Chrome tab ids** (tested 2026-11-09): `id of tab` survives closing other tabs, reordering by drag and tearing a tab off into another window. AppleScript's own `move tab …` does *not* move: it makes a new tab with a new id (and loses `data:` pages), so don't use it to test. Ids reset when Chrome restarts, hence the URL + title fallback.
- **Chrome tab strip in other languages and layouts:** header titles are localized (`group Beam - 7 Tabs`, German `Gruppe „Arbeit“ – 1 Tab`, Hebrew `\u202B הקבוצה עבודה – כרטיסייה אחת` with a bidi mark and the count spelled out). The header's DOM class is `TabGroupHeader` in the horizontal strip but `TabGroupHeaderView` with vertical tabs, where the strip is nested much deeper and each group sits in its own container. Tab buttons' AX titles also carry "– Memory usage – 32 MB" in some builds. Test with a throwaway profile: `open -n -a "Google Chrome" --args --user-data-dir=<dir> -AppleLanguages '(de)'`.
- **FSEvents callback paths:** without `kFSEventStreamCreateFlagUseCFTypes` the `eventPaths` pointer is a C array of C strings; bridging it as an `NSArray` segfaults on the first event.
- **Localized app names** come back in English from `FileManager.displayName` unless Info.plist sets `CFBundleAllowMixedLocalizations` (Beam itself has only English). German names contain soft hyphens (`System\u00ADeinstellungen`); strip them or typing doesn't match.
- **Chrome favicon mappings follow redirects:** `icon_mapping` links every URL in a redirect chain to the final page's icon, so `accounts.google.com/...` rows often carry Gmail/OpenAI/etc. icons. Match on the icon's own URL (`favicons.url`), not just `page_url`.
- **Any-order words:** only for 2+ query words, and longest word first when assigning target words, so "co core" can't spend "core" on "co" and fail.
- **Matcher scores are tier minus target length:** a prefix match on "Safari" is `prefix - 6`, not `>= prefix`. Fuzzy runs must start at a word boundary, so "sfr" does not match "Safari".
- **Windows on other Spaces:** `kAXWindowsAttribute` only returns windows on the current Space, and `CGWindowList` titles need Screen Recording. Enumerating by remote token is slow for apps with many windows: Chrome with ~20 windows needed element IDs past 1000 and ~1s. See `SpaceWindows.swift` and decision 0007.
- **Release signing:** a Developer ID build's designated requirement is already stable (bundle ID + Team ID + cert chain), so no `-r` pin is used in `scripts/release.sh`. But switching from the ad-hoc dev build to a Developer ID build changes the app's identity: re-grant Accessibility (`tccutil reset Accessibility com.beam.launcher`). Never use `codesign --deep` to sign; sign nested bundles individually, inside out. The hardened runtime needs `com.apple.security.automation.apple-events` for the Chrome AppleScript; Accessibility needs no entitlement.
- **Sparkle:** the framework is copied from `.build/artifacts/sparkle/...` in `make app` with an `@executable_path/../Frameworks` rpath (`install_name_tool` must run before signing). Release signing order is XPC services (`--preserve-metadata=entitlements`), `Autoupdate`, `Updater.app`, the framework, then the app; no `--deep`. `SUPublicEDKey` lives in `Info.plist`; the private key is only in the login Keychain (`generate_keys`), `make appcast` reads it from there. Sparkle compares `CFBundleVersion`, which must increase every release. When editing `Info.plist` with a text replace, beware of the nested `<dict>` in `CFBundleURLTypes`.
- **AppleScript:** `NSAppleScript` isn't thread-safe; run every script through `AppleScript.run` (one serial queue, never from the main thread). A `tell application id "…"` launches the app if it isn't running, even right after a Swift `isRunning` check, so wrap it in `if application id "…" is running then`. Tab focus waits behind an in-flight tab load on that queue.
- **Sparkle in dev builds:** the updater only starts when the app is signed with team `P9GCM9K6AH` (`CodeSigning.swift`), so `make run` has no "Check for Updates…". Test updates with `make release` builds.
- **Synthetic clicks** (`ChromeGroupProvider.click`) land on whatever is on top; `isHit` checks with `AXUIElementCopyElementAtPosition` that the point is in the same Chrome window first. Chrome does not hit-test to the group header element itself, so comparing elements always failed.
- **Chrome's Favicons DB** is locked and written by Chrome; don't open it in place (`immutable=1` on a changing file is undefined). `Favicons` reads an APFS clone of the DB + `-wal` in the temp dir.
- **Slack's cache:** group DMs carry `is_channel: true` too (their ids start with `C`), so check `is_mpim` before `is_channel`. The decoder must never trap on odd input (a negative double once did, via `UInt64(Int)`): it runs inside Beam on a file Slack can change in any update. Lengths are checked against the bytes left (never `pos + n`, which can overflow), and nesting is capped at 64 (real state is about 20 deep; the debug build's stack overflows long before 256).
- **Slack photos:** people's photos are on `ca.slack-edge.com` (`avatars.slack-edge.com` is apps and bots). A simple-cache entry's key starts at byte 24, not 20 (the header is padded), and keys look like `1/0/https://…` with no space before the URL. Some photos carry high-DPI metadata, so `NSImage.size` is set from the pixels, or they render a few points wide.
- **`.build/release` is a symlink:** `find .build/release` without `-H` doesn't follow it and finds nothing, which is how 0.1.1 shipped without the KeyboardShortcuts resource bundle and crashed when Settings opened. `release.sh` now refuses a bundle without it.
- **Mac App Store Slack** keeps its data in `~/Library/Containers/com.tinyspeck.slackmacgap/`. Reading another app's container triggers macOS's "access data from other apps" prompt (and `Operation not permitted` in a shell without it). The prompt appears at launch, since `refreshLive()` runs then, not when you first type `@`.

## Chrome's accessibility text is localized
Since 2026-11-09 (0011) tab groups are found by the tab strip's structure, and only the group name is parsed from the localized header text (English pattern, quoted names, or a learned "group" word); see the tab strip entry above. `WindowProvider.stripChromeGroup` still strips only the English " - Part of group …" suffix, which only matters for other Chromium browsers' window titles, since Chrome's own windows come from `ChromeProvider`. "Google Chrome" itself is a brand name and stays the same.

## Closed saved groups need the bookmarks bar
They come from the "Saved Tab Groups" toolbar (role description "saved tab group button", title "<name> group - Closed"/"Opened"). Hidden bookmarks bar means none found; English-only like the other group text. See 0016.
- **"Access data from other apps" denied:** macOS never asks again, and a rebuild with a new ad-hoc signature *does* ask again (it's a new app to TCC). Beam may list the container yet get `EPERM` on the file read, so the denial is checked on both. To get the prompt back by hand: `tccutil reset SystemPolicyAppData com.beam.launcher`. And check `defaults read com.beam.launcher BeamSimulateBrokenProvider` before trusting a "stopped working" row: it overrides the real outcome.
- **`ProviderHealth.d` is a global:** tests that swap it for a suite must stay in one test function (Swift Testing runs tests, and suites, in parallel). Two tests swapping it raced and left stale keys in the suite domain, failing the next run once.
- **Raising a window right as the panel closes can silently fail:** every AX call and SkyLight's set-front report success, yet the window stays behind (tab groups, 2026-11-10). Raise again from the background step, after the panel is gone (as the Chrome tab path does after its AppleScript). A collapsed group's header click also needs the window on top first.
